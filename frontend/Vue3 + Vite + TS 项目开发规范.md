# Vue3 \+ Vite \+ TS 项目开发规范

## 前言

本文档为前端 Vue3 项目统一开发规范，适用于所有基于 Vite \+ Vue3 \+ TypeScript 开发的后台管理系统、Web 业务项目。目的在于统一团队编码风格、统一目录结构、规范业务开发流程、提升项目可维护性与协作效率，所有项目开发均需严格遵守本规范。

## 一、项目目录规范

### 1\. 标准目录结构

```plain text
src
├── api          # 接口请求统一管理，按模块拆分文件
├── assets       # 静态资源：图片、全局样式、字体
├── components   # 公共通用组件（全局复用）
│   ├── base     # 基础组件：Button、Input、Modal、Table
│   └── business # 业务通用组件：搜索栏、文件上传、分页
├── hooks        # 组合式通用hooks，复用逻辑
├── layout       # 页面布局框架（侧边栏、头部、标签页）
├── router       # 路由，分路由模块、路由守卫
├── store        # Pinia 状态管理，按业务分模块
├── types        # TS全局类型、接口定义
├── utils        # 工具函数：日期、加密、校验、请求封装
├── views        # 页面业务页面，按功能模块分文件夹
├── App.vue      # 根组件
└── main.ts      # 入口文件
```

### 2\. 统一命名规则

- **文件夹**：小写短横线风格，例：`user-manage`

- **页面/组件文件**：大驼峰风格，例：`UserList.vue`

- **hooks/工具文件**：小驼峰风格，例：`useTable.ts`

- **常量/枚举**：全大写下划线风格，例：`STATUS_ENABLE`

## 二、代码语法规范

项目统一采用 **Vue3 \<script setup\>** 语法，禁止混用 Options API，保证代码风格统一。

- 组件参数、事件、暴露属性统一使用 `defineProps`、`defineEmits`、`defineExpose`

- Props 必须声明类型、默认值及必填校验，禁止空类型、滥用 any

- 复杂业务逻辑统一抽离至 hooks，单 Vue 文件代码不超过 300 行

- 禁止直接操作 DOM，优先使用 ref 绑定获取元素

```ts
// Props 标准写法
const props = defineProps<{
  id: number
  title?: string
}>()

// 带默认值写法
const props = withDefaults(defineProps<{title?: string}>(), { title: '' })
```

## 三、组件开发规范

- 通用公共组件存放 `components`，业务页面存放 `views`，严格区分

- 遵循单一职责原则，一个组件仅负责一类业务功能

- 组件样式统一开启 `scoped`，深度样式穿透统一使用 `:deep()`

- 父子组件通信：父传子使用 props，子传父使用 emit，禁止直接修改 props

- `v-for`必须绑定唯一 key，禁止使用 index 作为循环 key

- `v-if` 与 `v-for` 禁止同级使用，v\-for 需外层嵌套容器

## 四、路由规范

- 所有页面路由统一懒加载，实现分包打包，优化首屏加载速度

- 路由按业务模块拆分，统一路由守卫，处理登录校验、权限、页面标题

- 路由 name 与页面文件名保持一致，path 采用小写短横线命名

- 页面权限、菜单配置统一写入路由 meta，禁止页面硬编码权限

```ts
// 路由懒加载标准写法
const UserList = () => import('@/views/user/userList.vue')
```

## 五、Pinia 状态管理规范

- 按业务模块拆分 store 文件（用户、订单、字典等），禁止全部聚合

- 严格区分 state、getters、actions 职责，各司其职

- 异步接口请求统一写在 actions 中，组件仅调用方法，不处理请求逻辑

- 页面销毁时及时清空无用状态数据，避免内存堆积

## 六、接口请求规范

- 统一封装 Axios 实例，全局拦截请求头、响应状态码、统一错误提示

- 接口文件按业务模块拆分，一个接口对应一个函数，统一返回 Promise

- 封装通用分页、筛选、参数处理工具方法，统一参数格式

- 全局统一处理 401 登录过期、500 服务异常等错误场景

- 接口地址、超时时间、Token 等配置统一存放环境变量，禁止硬编码

## 七、TypeScript 规范

- 开启 TS 严格模式 `strict: true`，严禁滥用 any 类型

- 接口返回值、对象、列表数据提前定义 Interface/Type 类型

- 表单、请求参数、表格数据全部显式声明类型

- 所有业务状态统一使用枚举管理，统一状态标识

## 八、样式与 UI 规范

- 全局样式统一存放 `assets/css`，页面私有样式使用 scoped 隔离

- 统一使用 Element Plus / Arco Design 组件库，不重复封装基础组件

- 颜色、间距、尺寸统一使用全局 CSS 变量，禁止硬编码固定值

- 后台系统采用固定布局，移动端采用 rem/vw 适配方案

## 九、表单与表格开发规范

- 表单优先使用组件库原生校验规则，复杂校验抽离全局工具函数

- 表格分页、搜索、重置逻辑统一封装通用 useTable Hooks 复用

- 弹窗、抽屉通过布尔值控制显隐，禁止直接操作 DOM 控制弹窗

- 新增、编辑复用弹窗组件，通过状态字段区分业务场景


## 十、性能优化规范

- 大数据列表使用虚拟滚动，避免一次性渲染海量 DOM 节点

- 输入、滚动等高频事件统一添加防抖、节流处理

- 静态图片开启懒加载，大图片压缩处理，静态资源部署 CDN

- 计算逻辑统一使用 computed 缓存，避免重复计算

- 组件销毁时清除定时器、事件监听，杜绝内存泄漏

## 十一、注释规范

- 公共组件、工具函数、自定义 Hooks 必须添加功能、入参、返回值注释

- 复杂业务逻辑、特殊处理代码添加单行注释说明思路

- 接口函数注释需标注接口用途、请求参数、返回字段说明

- 废弃、无效代码直接删除，禁止注释保留在项目中
